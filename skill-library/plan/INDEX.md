# Plan Library Index

This index is read only after Tier 1 selected this category. Choose one workflow; do not load every workflow body.

| Workflow | Trigger / outcome |
|---|---|
| `course-correction` | Course correction — document the pivot, triage in-flight work, and update project direction. |
| `documents-academic-research` | Academic paper development — from first principles through submission. |
| `documents-narrative-arc` | Build and query a knowledge graph connecting strategic claims, proof points, objectives, and supporting/opposing evidence. |
| `epic-design` | Produce a complete, ordered story list for an epic. |
| `epics` | Manage epics and objectives — add, review, link, status, complete. Always loaded. |
| `product-brief` | Write a product brief — a strategic document describing what is being built, for whom, why it matters, and what success looks like. |
| `product-competition` | Competitive analysis at three depth levels — from a quick company survey to feature-by-feature deep analysis. |
| `product-discovery` | Establish what is being built, for whom, and why — at the depth appropriate for the project type. |
| `product-manage-scope` | Track scope changes when items move between in-scope and out-of-scope. |
| `product-market-messaging` | Craft external messaging — how you describe the product, the problem, and the value to different audiences. |
| `product-milestone-planning` | Guided milestone planning workshop. |
| `product-milestones` | Manage roadmap targets (milestones) that span strategy and product work. |
| `product-parking-lot` | Manage deferred work. |
| `product-positioning-statement` | Define how the product is positioned — for whom, what category, what differentiates it, and why that matters. |
| `product-prd` | Write a Product Requirements Document — functional requirements, non-functional requirements, epics, and success metrics. |
| `product-research` | Survey the solution field — what exists commercially and open source — so the user understands what they're entering before building. |
| `product-roadmap` | Manage the product roadmap — feature delivery targets, releases, and priority stack. |
| `product-roadmap-analysis` | RICE scoring and stack-rank analysis for roadmap items. |
| `product-terminology` | Define and maintain a shared domain glossary. |
| `product-user-focus-group` | Synthetic panel research using persona archetypes as parallel subagent respondents. |
| `product-user-stories` | Write user stories for a defined scope — Gherkin or generic format, scoped to all personas, SLC, or MVP. |
| `project-goals` | Manage project goals — binary business goals. |
| `project-scope` | Define and maintain project scope. |
| `user-personas` | Define product users — who they are, what they need to do, and exactly what completing each task looks and feels like. |
