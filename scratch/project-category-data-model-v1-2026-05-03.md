# SweetClaude Project Category — Data Model
**Version:** 1.2  
**Date:** 2026-05-03  
**Status:** DRAFT — design review pending  
**Authors:** Carson Sweet + Claude

---

## Overview

This document defines the canonical data model for the new **Project** category in SweetClaude. It covers eight entity types, their fields, relationships, Markdown file templates, SQLite table definitions, a storage abstraction interface, directory layout, and migration plan for existing artifacts.

**Backlog is not an entity type.** It is a view: the set of Issues where `sprint_id IS NULL`. The `project-backlog` skill renders this view and supports promoting issues into a sprint. There are no `BL-NNN` files.

### Design constraints

- Every schema works as both a Markdown `.md` file AND a SQLite table row (dual representation)
- Skills never access storage directly — they go through the storage adapter (`sc_artifact_*` functions)
- All cross-artifact references use IDs (never file paths), so moves and archives do not break links
- Every entity carries `mode_introduced` — which project mode first required this artifact type
- Scope changes cascade top-down: milestones → epics → roadmap → backlog → sprints
- Mode transitions snapshot current state before executing upshift/downshift
- SQLite is optional: default for Agile Enterprise, opt-in for Agile, unavailable for Flow/Kanban/Shape Up
- Flow mode artifacts are inferred (never user-authored) and carry `source: inferred` + `evidence` fields

## Entity Map

```
Scope (singleton)
  └── triggers cascade on change

Milestone (MS-NNN)
  └── optionally references: Release

Release (REL-NNN)
  └── bundles: Roadmap Items (1..many)
  └── optionally triggers: Milestone

Roadmap Item (RM-NNN)
  └── optionally belongs to: Release
  └── decomposes into: Epics (0..many) OR Issues (0..many, direct)

Epic (EP-NNN)
  └── optionally references: Roadmap Item
  └── contains: Issues (1..many)

Issue (I-NNN)
  └── optionally belongs to: Epic (exclusive — one issue, one epic)
  └── optionally scheduled in: Sprint
  └── status = backlog, sprint_id IS NULL → appears in backlog view

Sprint (SP-NNN)
  └── composed of: Issues (1..many)

Pitch (PITCH-NNN) — Shape Up mode only
  └── independent of all above
```

### Mode availability matrix

`inferred` = artifact exists but is auto-generated by background observation, never user-authored

| Entity | Flow | Kanban | Shape Up | Agile | Agile Enterprise |
|---|---|---|---|---|---|
| Issue | inferred | ✓ | — | ✓ | ✓ |
| Epic | — | — | — | optional | recommended |
| Sprint | — | — | — | ✓ | ✓ |
| Roadmap Item | — | ✓ | — | ✓ | ✓ |
| Release | — | optional | — | optional | ✓ |
| Milestone | — | optional | optional | ✓ | ✓ |
| Scope | — | optional | — | ✓ | ✓ |
| Pitch | — | — | ✓ | — | — |

*Backlog is a filtered view of Issues (sprint_id IS NULL) — no separate entity or row in this matrix.*

## Storage Backends

### Markdown (default)
- One `.md` file per artifact, structured markdown with bold key-value metadata block
- `project-index.json` generated by `state-regenerator` hook — used for cross-reference queries
- Git-friendly: diffs are readable, merge conflicts are resolvable
- Human-readable: open any file to understand project state

### SQLite (opt-in: Agile / default: Agile Enterprise)
- Single `.sweetclaude/state/project.db` file
- Generated from Markdown on upshift; exported to Markdown on downshift
- Enables complex joins across entities
- Git: `.db` committed but diffs are binary — Markdown export kept in sync for readable history

### Storage adapter interface

Skills call these shell functions — never read/write files or SQL directly:

```bash
sc_artifact_read  <id>                      # → JSON object
sc_artifact_write <id> <json>               # update existing
sc_artifact_create <type> <json>            # → new artifact with assigned ID
sc_artifact_query <type> [key=value ...]    # → JSON array
sc_artifact_delete <id>                     # soft delete (sets status=cancelled)
sc_artifact_list  <type>                    # → JSON array of all non-cancelled
```

The adapter resolves which backend is active from `phase.yaml → storage_backend`.

## Flow Mode — Passive Observation

Flow mode is SweetClaude as a **code archaeologist**: it watches, infers, and records without ever interrupting the developer's natural work. No skills are surfaced, no phase gates are enforced, no status panels appear on startup. At most, a single line: `"SweetClaude observing."` — or nothing at all.

### What runs in the background

| Source | What is inferred | Artifact created |
|---|---|---|
| Git commit messages | Classify as story / bug / chore by message pattern | Draft Issue (`source: inferred`) |
| Git branch names | `feature/*`, `fix/*`, `chore/*` signal work type and area | Annotates inferred Issues |
| TODO / FIXME scan | Comments in code surface as potential work items | Draft Issue (`source: inferred`, `status: backlog`) |
| Commit frequency + file churn | Signals which areas are actively changing | Stored as project activity metadata |
| Complexity signal | Rising issue count, file count, collaborator count | One-time light suggestion to upshift (never repeated) |

### Upshift value proposition

When the user decides to move to Kanban or Agile, Flow mode's inferred artifacts become the starting inventory. Instead of blank templates, the user sees: "Here's what I observed — 18 inferred issues, 4 rough work areas, a draft backlog. Promote, edit, or discard each one." The archaeologist hands off the dig to the architect.

### Session start behavior (Flow mode)

`session-preflight.sh` checks `phase.yaml → mode`. If `flow`:
- Run background inference (git scan, TODO scan) silently
- Output at most: `"SweetClaude observing."` — no status panel, no skill suggestions
- No `sweetclaude:status` invocation

### 1. Issue `I-NNN`

The atomic work unit. Self-contained enough for a developer to pick up, write TDD tests, implement, and ship without requiring additional context. Issues with `sprint_id IS NULL` form the backlog view.

#### Canonical fields

| Field | Type | Required | Notes |
|---|---|---|---|
| id | string | ✓ | I-NNN, auto-assigned |
| title | string | ✓ | |
| type | enum | ✓ | story \| bug \| chore \| spike |
| status | enum | ✓ | backlog \| ready \| in_progress \| in_review \| done \| cancelled |
| priority | enum | — | now \| sooner \| soonish \| later \| someday. Triage estimate, not force-rank. |
| effort | enum | — | xs \| s \| m \| l \| xl \| xxl. Sizing estimate for planning. |
| epic_id | string | — | EP-NNN. Null if standalone. Exclusive — one issue belongs to at most one epic. |
| sprint_id | string | — | SP-NNN. Current sprint. Null if unscheduled (backlog). |
| sprint_history | list | — | All sprints this issue has touched. Each entry: `{sprint_id, added_date, removed_date, outcome: completed \| carried_over \| descoped}`. Used to detect adrift issues. |
| roadmap_item_id | string | — | RM-NNN. Set if issue is directly under a roadmap item (no epic). |
| description | text | ✓ | "As a [user], I want [X]" for stories. Bug reproduction steps for bugs. Task description for chores. Research question for spikes. |
| acceptance_criteria | list | ✓ (story/bug) | Binary conditions. Each is true/false evaluable. |
| tdd_feature_file | string | — | Path to `.feature` file if Gherkin tests were written. |
| appetite | string | — | Spike only. Time budget e.g. "1 day". |
| spike_output_type | enum | — | Spike only. decision \| prototype \| recommendation |
| spike_output | text | — | Spike only. Filled when done. |
| source | enum | ✓ | manual \| inferred \| imported. Flow mode sets `inferred`. |
| evidence | string | — | Basis for inferred issues: commit hash, file:line, branch name. Null for manual. |
| mode_introduced | enum | ✓ | The project mode that first required this artifact. |
| created_at | date | ✓ | |
| updated_at | date | ✓ | |

#### Markdown template

```markdown
# I-NNN: Issue title

**Type:** story
**Status:** backlog
**Priority:** sooner
**Effort:** m
**Epic:** EP-001
**Sprint:** (SP-NNN when scheduled)
**Roadmap Item:** RM-001
**Source:** manual
**Evidence:** (commit abc1234 or file:line — Flow mode only)
**Sprint history:** SP-001 (carried_over), SP-002 (carried_over), SP-003 (in progress)
**Created:** 2026-05-03
**Updated:** 2026-05-03

## Description

As a [user], I want [capability] so that [outcome].

## Acceptance criteria

- [ ] Condition one is true
- [ ] Condition two is true
- [ ] Edge case is handled

## Notes

Additional context, links, or technical notes.
```

For **spike** type, replace Acceptance criteria with:

```markdown
## Research question

What is [the thing we need to know]?

**Appetite:** 1 day
**Output type:** decision

## Output

(Filled when done)
```

#### SQLite DDL

```sql
CREATE TABLE issues (
  id              TEXT PRIMARY KEY,           -- 'I-001'
  title           TEXT NOT NULL,
  type            TEXT NOT NULL CHECK (type IN ('story','bug','chore','spike')),
  status          TEXT NOT NULL DEFAULT 'backlog'
                    CHECK (status IN ('backlog','ready','in_progress','in_review','done','cancelled')),
  priority        TEXT CHECK (priority IN ('now','sooner','soonish','later','someday')),
  effort          TEXT CHECK (effort IN ('xs','s','m','l','xl','xxl')),
  epic_id         TEXT REFERENCES epics(id),
  sprint_id       TEXT REFERENCES sprints(id),
  sprint_history  TEXT DEFAULT '[]',          -- JSON: [{sprint_id, added_date, removed_date, outcome}]
  roadmap_item_id TEXT REFERENCES roadmap_items(id),
  description     TEXT NOT NULL,
  acceptance_criteria TEXT,                   -- JSON array of strings
  tdd_feature_file TEXT,
  appetite        TEXT,                       -- spike only
  spike_output_type TEXT CHECK (spike_output_type IN ('decision','prototype','recommendation')),
  spike_output    TEXT,
  source          TEXT NOT NULL DEFAULT 'manual'
                    CHECK (source IN ('manual','inferred','imported')),
  evidence        TEXT,                       -- Flow mode: commit hash, file:line, branch
  mode_introduced TEXT NOT NULL,
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL
);

CREATE INDEX idx_issues_epic        ON issues(epic_id);
CREATE INDEX idx_issues_sprint      ON issues(sprint_id);
CREATE INDEX idx_issues_status      ON issues(status);
CREATE INDEX idx_issues_type        ON issues(type);
CREATE INDEX idx_issues_priority    ON issues(priority);

-- Backlog view: issues not yet in a sprint
CREATE VIEW backlog AS
  SELECT * FROM issues WHERE sprint_id IS NULL AND status NOT IN ('done','cancelled');

-- Sprint history — separate table for queryable adrift detection
CREATE TABLE issue_sprint_history (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  issue_id     TEXT NOT NULL REFERENCES issues(id),
  sprint_id    TEXT NOT NULL REFERENCES sprints(id),
  added_date   TEXT NOT NULL,
  removed_date TEXT,
  outcome      TEXT CHECK (outcome IN ('completed','carried_over','descoped'))
);

CREATE INDEX idx_sprint_history_issue   ON issue_sprint_history(issue_id);
CREATE INDEX idx_sprint_history_sprint  ON issue_sprint_history(sprint_id);
CREATE INDEX idx_sprint_history_outcome ON issue_sprint_history(outcome);
-- Adrift query: SELECT issue_id FROM issue_sprint_history WHERE outcome='carried_over' GROUP BY issue_id HAVING COUNT(*) >= 2
```

### 2. Epic `EP-NNN`

Optional planning container for 4–12 related issues. Not a sprint commitment unit. Exists only when grouping adds clarity.

#### Canonical fields

| Field | Type | Required | Notes |
|---|---|---|---|
| id | string | ✓ | EP-NNN |
| title | string | ✓ | |
| status | enum | ✓ | active \| complete \| cancelled |
| roadmap_item_id | string | — | RM-NNN. Null if epic is standalone. |
| goal | string | ✓ | "When this ships, [user outcome] becomes possible." One sentence. |
| description | text | — | |
| mode_introduced | enum | ✓ | |
| created_at | date | ✓ | |
| updated_at | date | ✓ | |

**Issue membership** is tracked on the Issue (via `epic_id`), not stored as a list on the Epic.

#### Markdown template

```markdown
# EP-NNN: Epic title

**Status:** active
**Roadmap Item:** RM-002
**Goal:** When this ships, [user outcome] becomes possible.
**Created:** 2026-05-03
**Updated:** 2026-05-03

## Description

What this epic covers and why it is grouped together.

## Issues

See issues with `Epic: EP-NNN` in their metadata.

## Definition of done

Clear statement of what "complete" looks like for this epic.
```

#### SQLite DDL

```sql
CREATE TABLE epics (
  id              TEXT PRIMARY KEY,
  title           TEXT NOT NULL,
  status          TEXT NOT NULL DEFAULT 'active'
                    CHECK (status IN ('active','complete','cancelled')),
  roadmap_item_id TEXT REFERENCES roadmap_items(id),
  goal            TEXT NOT NULL,
  description     TEXT,
  mode_introduced TEXT NOT NULL,
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL
);

CREATE INDEX idx_epics_roadmap_item ON epics(roadmap_item_id);
CREATE INDEX idx_epics_status       ON epics(status);
```

### 3. Sprint `SP-NNN`

Time-boxed execution unit. Committed to a **goal** (outcome), composed of individual issues. Time is fixed; scope is the variable.

#### Canonical fields

| Field | Type | Required | Notes |
|---|---|---|---|
| id | string | ✓ | SP-NNN |
| title | string | ✓ | e.g. "Sprint 12" or "Sprint 2026-05-01" |
| status | enum | ✓ | planned \| active \| complete \| cancelled |
| start_date | date | ✓ | |
| end_date | date | ✓ | |
| goal | string | ✓ | Outcome commitment. What is true when this sprint succeeds. |
| capacity_notes | text | — | Team availability, known interrupts. |
| velocity | integer | — | Count of issues completed. Filled post-sprint. |
| retrospective | text | — | Filled post-sprint. |
| mode_introduced | enum | ✓ | |
| created_at | date | ✓ | |
| updated_at | date | ✓ | |

**Issue membership** tracked on Issue (via `sprint_id`). A sprint is locked once active — new issues go to the next sprint.

#### Markdown template

```markdown
# SP-NNN: Sprint title

**Status:** planned
**Start:** 2026-05-06
**End:** 2026-05-20
**Created:** 2026-05-03
**Updated:** 2026-05-03

## Goal

When this sprint succeeds, [outcome statement].

## Issues

See issues with `Sprint: SP-NNN` in their metadata.

## Capacity notes

(Optional: known interrupts, holidays, reduced availability.)

---

## Retrospective

(Filled post-sprint.)

**Velocity:** (issue count completed)
```

#### SQLite DDL

```sql
CREATE TABLE sprints (
  id              TEXT PRIMARY KEY,
  title           TEXT NOT NULL,
  status          TEXT NOT NULL DEFAULT 'planned'
                    CHECK (status IN ('planned','active','complete','cancelled')),
  start_date      TEXT NOT NULL,
  end_date        TEXT NOT NULL,
  goal            TEXT NOT NULL,
  capacity_notes  TEXT,
  velocity        INTEGER,
  retrospective   TEXT,
  mode_introduced TEXT NOT NULL,
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL
);

CREATE INDEX idx_sprints_status ON sprints(status);
```

### 4. Roadmap Item `RM-NNN`

A planned feature, enhancement, or sunset. Force-ranked by priority. Type determines which downstream workflow is invoked when activated. Chores, bugs, and spikes do not appear on the roadmap — they are managed as Issues.

#### Canonical fields

| Field | Type | Required | Notes |
|---|---|---|---|
| id | string | ✓ | RM-NNN |
| title | string | ✓ | |
| type | enum | ✓ | major_feature \| minor_feature \| enhancement \| sunset |
| status | enum | ✓ | idea \| planned \| in_progress \| complete \| cancelled \| deferred |
| priority | integer | ✓ | Force-ranked. 1 = highest. |
| release_id | string | — | REL-NNN. Null if not in a release. |
| description | text | ✓ | What this is and why it belongs on the roadmap. |
| rationale | text | ✓ | Why now, at this priority. |
| workflow_template | enum | computed | Derived from type. Not stored. |
| mode_introduced | enum | ✓ | |
| created_at | date | ✓ | |
| updated_at | date | ✓ | |

**Workflow template derivation** (computed, not stored):

| Type | Workflow template |
|---|---|
| major_feature | net_new_feature |
| minor_feature | enhancement_iteration |
| enhancement | enhancement_iteration |
| sunset | api_deprecation |

#### Markdown template

```markdown
# RM-NNN: Roadmap item title

**Type:** major_feature
**Status:** planned
**Priority:** 2
**Release:** REL-001
**Created:** 2026-05-03
**Updated:** 2026-05-03

## Description

What this is.

## Rationale

Why this is on the roadmap at this priority, and why now.

## Epics

See epics with `Roadmap Item: RM-NNN` in their metadata.

## Notes

```

#### SQLite DDL

```sql
CREATE TABLE roadmap_items (
  id              TEXT PRIMARY KEY,
  title           TEXT NOT NULL,
  type            TEXT NOT NULL
                    CHECK (type IN ('major_feature','minor_feature','enhancement','sunset')),
  status          TEXT NOT NULL DEFAULT 'planned'
                    CHECK (status IN ('idea','planned','in_progress','complete','cancelled','deferred')),
  priority        INTEGER NOT NULL,
  release_id      TEXT REFERENCES releases(id),
  description     TEXT NOT NULL,
  rationale       TEXT NOT NULL,
  mode_introduced TEXT NOT NULL,
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL
);

CREATE INDEX idx_roadmap_items_status   ON roadmap_items(status);
CREATE INDEX idx_roadmap_items_priority ON roadmap_items(priority);
CREATE INDEX idx_roadmap_items_release  ON roadmap_items(release_id);
CREATE INDEX idx_roadmap_items_type     ON roadmap_items(type);
```

Binary business goal. Happened or it didn't. May be triggered by a release or by any other external event.

#### Canonical fields

| Field | Type | Required | Notes |
|---|---|---|---|
| id | string | ✓ | MS-NNN |
| title | string | ✓ | |
| status | enum | ✓ | pending \| achieved \| missed \| cancelled |

| achieved_at | date | — | Filled when achieved. |
| release_id | string | — | REL-NNN. The release that triggered this, if any. |
| description | text | — | Context and motivation. |
| mode_introduced | enum | ✓ | |
| created_at | date | ✓ | |
| updated_at | date | ✓ | |

#### Markdown template

```markdown
# MS-NNN: Milestone title

**Status:** pending
**Release:** REL-001
**Achieved:** (date when achieved)

**Updated:** 2026-05-03

(Binary condition — "this happened or it didn't")
```

```sql
CREATE TABLE milestones (
```

### 7. Scope (singleton)

Project scope definition. A single document. Changes cascade through the project hierarchy. Version-incremented on every change.

#### Canonical fields (YAML — machine-read)

```yaml
# .sweetclaude/state/scope.yaml
schema_version: 1
version: 3
last_changed: 2026-05-03
statement: "One-sentence description of what this project does and for whom."
in_scope:
  - "Item 1"
  - "Item 2"
out_of_scope:
  - "Item A"
  - "Item B"
change_log:
  - date: 2026-05-03
    change: "Added mobile support to in-scope"
    cascade_triggered: true
    snapshot_id: SNAPSHOT-002
created_at: 2026-04-01
```

#### SQLite DDL

```sql
CREATE TABLE scope (
  id              INTEGER PRIMARY KEY DEFAULT 1,  -- always 1, singleton
  schema_version  INTEGER NOT NULL DEFAULT 1,
  version         INTEGER NOT NULL DEFAULT 1,
  last_changed    TEXT NOT NULL,
  statement       TEXT NOT NULL,
  in_scope        TEXT NOT NULL,                  -- JSON array
  out_of_scope    TEXT NOT NULL,                  -- JSON array
  change_log      TEXT NOT NULL DEFAULT '[]',     -- JSON array
  created_at      TEXT NOT NULL
);
```

### 8. Pitch `PITCH-NNN` — Shape Up mode only

Shaped work description. Contains the problem, proposed solution, appetite (time budget), and explicit rabbit holes to avoid.

#### Canonical fields

| Field | Type | Required | Notes |
|---|---|---|---|
| id | string | ✓ | PITCH-NNN |
| title | string | ✓ | |
| status | enum | ✓ | draft \| ready \| bet \| in_cycle \| shipped \| cancelled |
| appetite | enum | ✓ | two_weeks \| six_weeks |
| problem | text | ✓ | The problem being solved. Concrete scenario. |
| solution | text | ✓ | The proposed approach. Not exhaustive — leaves room for implementation. |
| rabbit_holes | list | — | Risks and scope traps to explicitly avoid. |
| no_gos | list | — | Things this pitch will not do. |
| mode_introduced | enum | ✓ | Always shape_up. |
| created_at | date | ✓ | |
| updated_at | date | ✓ | |

#### Markdown template

```markdown
# PITCH-NNN: Pitch title

**Status:** draft
**Appetite:** six_weeks
**Created:** 2026-05-03
**Updated:** 2026-05-03

## Problem

Concrete description of the problem. Who is affected and how.
Include a specific scenario or example.

## Solution

The proposed approach. Should be specific enough to build from
but not so detailed it removes implementation decisions from the team.

## Rabbit holes

- Risk or scope trap to avoid
- Another thing to watch out for

## No-gos

- Explicitly out of scope for this pitch
```

#### SQLite DDL

```sql
CREATE TABLE pitches (
  id              TEXT PRIMARY KEY,
  title           TEXT NOT NULL,
  status          TEXT NOT NULL DEFAULT 'draft'
                    CHECK (status IN ('draft','ready','bet','in_cycle','shipped','cancelled')),
  appetite        TEXT NOT NULL CHECK (appetite IN ('two_weeks','six_weeks')),
  problem         TEXT NOT NULL,
  solution        TEXT NOT NULL,
  rabbit_holes    TEXT DEFAULT '[]',              -- JSON array
  no_gos          TEXT DEFAULT '[]',              -- JSON array
  mode_introduced TEXT NOT NULL DEFAULT 'shape_up',
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL
);
```

|---|---|
| `project-milestones` | Create, update, and view milestones (binary business goals) |

## Open Questions

1. **Mode-shift skill**: `project-mode` needs to handle initial mode selection AND bidirectional transitions. Treating it as two operations (assess + transition) vs. one skill is a design decision for the tech spec phase.

2. **project-index.json schema**: The cross-reference index format needs its own spec. Should mirror the entity schemas above but optimized for the queries skills actually run.

3. **Flow inference scope**: Which background inferences run at session start vs. continuously (PostToolUse hook)? Git scan on startup is cheap. TODO scan on every file write could be noisy. Define the trigger model for each inference source before implementing the Flow mode hooks.
